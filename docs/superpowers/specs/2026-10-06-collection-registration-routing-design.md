# 收藏、注册与路由升级设计

## 目标

在现有文章列表、文章详情和登录功能上补齐文章收藏、取消收藏、账号注册、我的收藏列表和首页侧边栏，并使用 `go_router` 统一管理页面导航。实现继续采用 Dio、Riverpod、Freezed、json_serializable 和安全 Cookie 存储。

## 技术方案

### 共享认证客户端

新增持久化会话客户端，内部持有同一个 Dio 和 `PersistCookieJar`。文章、认证和收藏 Repository 共享该客户端，因此登录、注册和收藏请求会自动携带同一份 Cookie。现有仅用于测试的 Repository 注入接口继续保留。

### 数据模型

`Article` 使用 Freezed 增加：

- `collected`：解析接口字段 `collect`，表示文章当前是否已收藏。
- `originId`：收藏列表中的原文章编号；收藏列表取消收藏时与收藏记录编号配合使用。

普通文章使用 `id` 调用收藏和取消收藏接口；收藏列表使用收藏记录 `id` 调用删除接口，并提交 `originId`。

### 登录与注册

登录页增加登录、注册两种模式。注册模式显示确认密码输入框，校验两次密码一致，然后调用注册接口。注册成功后立即调用登录接口建立 Cookie 会话，并把登录用户写入原有 `AuthController`。

登录、注册和退出继续通过同一个认证队列串行执行，防止多个请求交叉修改 Cookie。

### 收藏状态

新增 `CollectionService` 和 Riverpod `CollectionController`：

- 登录后读取 `/lg/collect/list/0/json`，建立当前账号的收藏列表和文章收藏状态。
- 普通列表收藏调用 `/lg/collect/{id}/json`。
- 普通列表取消收藏调用 `/lg/uncollect_originId/{id}/json`。
- 收藏页取消收藏调用 `/lg/uncollect/{recordId}/json`，表单参数为 `originId`。
- 同一篇文章请求进行中禁用收藏按钮。
- 请求成功后才改变已确认状态；失败保持原状态并显示原因。
- 登录用户变化时重新建立收藏状态，避免不同账号之间串数据。

未登录点击收藏按钮时进入登录/注册页。登录成功后返回文章列表，用户再次点击即可执行收藏，与参考项目保持一致。

### 页面与路由

引入 Flutter 团队维护的 `go_router`，应用改用 `MaterialApp.router`。集中声明以下命名路由：

- `/`：文章列表。
- `/article`：文章详情，通过 `GoRouterState.extra` 传递 `Article`。
- `/account`：登录/注册页面。
- `/collections`：我的收藏。

页面使用 `context.pushNamed` 和 `context.pop` 导航，不再直接创建 `MaterialPageRoute`。Widget 测试仍可通过页面构造参数注入替身页面，保证局部测试简单稳定。

文章列表 Scaffold 增加标准 Drawer。侧边栏只保留“登录/注册”和“我的收藏”两个入口；点击后先关闭 Drawer，再通过命名路由打开对应页面。

### 页面交互

- 每张文章卡片右下角展示收藏图标，已收藏使用实心图标。
- 收藏请求期间图标显示进度且不能重复点击。
- 我的收藏页面支持加载、空数据、错误重试和下拉刷新。
- 收藏页点击文章进入同一个文章详情页面。
- 收藏页取消成功后立即移除对应文章。
- 未登录进入我的收藏页时展示登录提示和“去登录”按钮。

## 错误处理

- Repository 统一把业务错误、HTTP 错误、连接错误和解析错误转换为可读异常。
- 收藏失败保留原图标状态并通过 SnackBar 显示原因。
- 注册失败停留在注册模式并保留输入内容。
- 收藏列表刷新失败保留已经加载的数据，只显示轻量提示。
- 路由缺少或收到错误类型的文章参数时展示可读错误页，避免强制类型转换崩溃。

## 验收标准

1. 文章列表每篇文章都有可用的收藏按钮。
2. 未登录收藏会进入登录/注册页，已登录收藏会请求服务端并更新图标。
3. 用户可以在同一页面切换登录与注册，注册成功后处于登录状态。
4. 首页侧边栏只有两个业务入口，并能到达登录/注册与我的收藏页面。
5. 我的收藏可以展示服务端数据、进入详情和取消收藏。
6. 所有页面导航由 `go_router` 管理。
7. 自动测试、静态检查和 iOS 模拟器构建全部通过。
